这次重构的终极目标是：优化userSession，让它更易于阅读、理解。

userSession在这里的作用是：已登录用户的总控制器。为了体现它目前的地位，可以在controller包下面，单独创建一个usersession文件夹，
里面提供一个主入口，然后按照用户类型的不同，把控制器拆分成管理员和普通用户各自的总控制器。然后应用策略模式、工厂模式和命令模式的结合，
对这个超级控制器进行改造。

为了避免重构时，状态管理与业务逻辑耦合在一起，事实上的第一步是剥离出状态机。
这是程序的所有状态信息：

    /**
     * 用户已登录，应该进入已登录用户的会话页面。
     */
    public static final int STATE_USER_AUTHENTICATED = 1;
    /**
     * 用户未登录，需要注册为新用户，或者作为老用户登录。
     */
    public static final int STATE_LOGIN_FLOW = 2;
    /**
     * 退出程序。
     */
    public static final int STATE_EXIST = 0;
    /**
     * &emsp;&emsp;这个字段决定是否需要退出程序。当它等于0时，程序正常退出。
     * 否则，根据程序状态，执行对应的流程。<br>
     * &emsp;&emsp;它只能由控制器来改变。
     */
    protected int CURRENT_STATE;
    
状态变化流程如下：
默认状态固定为STATE_OFFLINE。此时，用户只能选择进入注册流，或者进入登录流。现有流程中，进入登录流后，用户还可以选择注册或登录。一旦注册成功，并不意味着直接登录，
而是重新回到默认状态，即离线状态，用户重新决定注册或者登录。
只有彻底登录成功，就可以进入STATE_USER_AUTHENTICATED状态。

只要状态改变的请求不符合这个流程，就一律阻止。
